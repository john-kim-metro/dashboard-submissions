Notes for the development team

What this app is for, how it should work, and what in this mockup is real versus simulated.

The admin dashboard is for demonstration purposes only. Every number and chart on it comes from generated sample data. It is not connected to ModMed, the MSSQL data dump, or any app database. It shows the intended layout and metrics, not real results.

Purpose

A simple CRM for our outreach field agent to track referring providers. The agent finds a provider, logs each interaction, and keeps office details up to date. Admins use a dashboard to see outreach activity and whether it lines up with new patient referrals. We benchmarked Salesforce; this app deliberately covers only what we need, so it stays fast and simple to use in the field.

How it works

Provider list

ModMed is the source of truth. Provider records come from the daily ModMed data dump already loaded into our MSSQL database. The app reads these records and never edits them; corrections happen in ModMed.

Office details

The agent can add information ModMed doesn't hold, such as office hours, number of employees, office manager, and best time to visit. Store this in the app's own table, keyed to the ModMed provider ID, so the nightly refresh never overwrites it.

Preliminary providers

If the agent visits an office that isn't in ModMed, they can add the provider in the app. These records are marked Preliminary (Not in EHR). When a record with the same NPI appears in the ModMed dump, the preliminary record is matched to it, its interactions and office details move over, and the label is removed. Uncertain matches go to an admin for review.

Logging interactions

Each interaction records the provider, type (Email, Call, Pre-arranged visit, Drop by), date and time, and the agent. The agent records a short voice note; the app transcribes it and generates a brief summary. Both are saved and shown: the transcript stays as recorded, and the summary can be edited. Typed notes are a fallback. Speech-to-text and summarization must use a HIPAA-eligible service covered by a signed BAA, since notes may mention patient details.

Editing summaries

The agent can edit a saved summary to fix transcription mistakes or add details. The recorded transcript is never changed. Keep the original AI summary and record who edited it and when, so the history is auditable.

Action items

Each provider page has a simple checklist of follow-ups (text and an optional due date) that can be checked off. Completed items stay visible, crossed off. A separate Action items tab lists open items across all providers, grouped as overdue, due in the next 7 days, later, and no due date.

Admin dashboard

Shows interactions by action type and date range, providers reached, and new patient referrals per provider over time, with outreach dates marked so trends can be compared before and after visits. A new patient referral is counted when the patient's first appointment is created in ModMed, regardless of appointment status.

What's simulated in this mockup

Everything runs in the browser with sample data, and nothing is saved; a refresh resets it. Voice recording, transcription, AI summaries, and the NPI lookup are simulated. All providers, names, and phone numbers are fictional. The admin dashboard is a demonstration only, as noted above.
